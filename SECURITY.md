# Политика безопасности

## Поддерживаемые версии

Проект опубликован как `0.4.x`; исправления безопасности выходят только для
**последней** версии из `version.json` / `CHANGELOG.md`.

| Версия | Поддержка |
|---|---|
| последняя `0.4.x` | да |
| более старые | нет, обновитесь |

## Как сообщить об уязвимости

Пожалуйста, **не публикуйте детали эксплойта** в открытом виде до исправления.

1. Создайте Issue в GitHub с пометкой **[SECURITY]** в заголовке:
   `[SECURITY] Краткое описание`.
2. Укажите:
   - версию пульта (`version.json`);
   - модель и прошивку колонки;
   - шаги воспроизведения;
   - ожидаемое и фактическое поведение;
   - есть ли риск выполнения команд от root.
3. Если GitHub позволяет private security advisory — используйте его вместо
   публичного Issue.

Проект поддерживается одним автором, поэтому фиксированного срока ответа нет.
По возможности подтвержу получение и предложу план исправления. Публичное
раскрытие деталей — после выхода патча или по согласованию с автором.

## Модель безопасности

- Проект рассчитан на **уже рутованную** колонку и запускается от root.
  Скриптов получения root, подмены DNS, установки ключей eMudhra и подобных
  эксплойтов в репозитории **нет и не будет**.
- Панель работает по **HTTP** в локальной сети на порту `8055`.
  Публиковать порт в интернет нельзя. TLS в проекте нет: PIN, cookie и токен
  идут по сети открыто, поэтому используйте только доверенную LAN или VPN;
  для недоверенной сети ставьте HTTPS-прокси перед панелью.
- PIN опционален. При включении он проверяется на сервере: без куки отдаётся
  только страница входа, `/index.html` запрещён, CGI и `/state` отвечают 401.
  Luna слушает только `127.0.0.1:8099`; панель ходит в неё через
  `/cgi-bin/luna.py` с проверкой PIN. Mutating-действия требуют POST и
  same-origin; GET-ссылки их не запускают.
  Запросы с localhost (сам пульт и демоны) проходят без PIN.
- Секреты (ключи LLM, VPN-подписка, Glagol-токен, PIN-хэш, чаты) хранятся в
  `/data/mypult` с правами `600` и не попадают в репозиторий.
- Резервная копия из панели **содержит секреты** — её нельзя прикладывать к
  Issue или коммитить.
- HTTPS не используется: самоподписанный сертификат даёт предупреждение, а
  Let's Encrypt требует публичный домен.

## Исходящие запросы (SSRF)

- Каждый исходящий HTTP(S)-запрос из CGI строится на `common.url_guard()` и
  `common.open_url()`. Guard проверяет схему (обычно только `https`),
  отсутствие `user:pass` в URL и все адреса, в которые резолвится хост:
  link-local/метаданные, `0.0.0.0` и multicast запрещены всегда; loopback и
  приватные сети — только с явным флагом или хостом из
  `/data/mypult/url_allow.json`.
- `common.open_url()` — обёртка над `urlopen` с `GuardedRedirectHandler`:
  **каждый** redirect (301/302/303/307/308) проверяется тем же guard, что и
  исходный адрес. Публичный URL, который редиректит в loopback, LAN или
  метаданные, отклоняется; обычный публичный redirect работает.
- `same_host=True` (LLM) дополнительно требует совпадения хоста **и порта** с
  исходным URL: `Authorization` не уходит на другой хост по redirect. В `ask`
  это даёт `502` «Неожиданный ответ API»; `fetch_models` при такой ошибке
  молча откатывается на публичный каталог или встроенный список моделей.
- Где какой режим:
  - HTTP-действия сценариев — `http`/`https`, приватная LAN разрешена,
    loopback только через allowlist. Отказ виден в `errors` запуска сценария
    (`адрес запрещён` / `redirect … запрещён`).
  - VPN-подписка — только `https` и только публичный хост.
  - LLM `ask`/`fetch_models` — `same_host`; `base_url` может быть локальным
    (свой OpenAI-совместимый сервер на колонке или в LAN). Это осознанное
    исключение: адрес задаёт владелец колонки, ключ уходит только на него.
  - Обновление — `api_guard` пропускает только `https://api.github.com` и хост
    из dev-переменной `MYPULT_UPDATE_API` (он всё равно обязан быть публичным
    `https`); `asset_guard` — только `https`-хосты GitHub (`github.com`,
    `objects.githubusercontent.com`, `release-assets.githubusercontent.com`,
    `codeload.github.com`). Оба guard'а срабатывают на каждом хопе redirect.
- `sing-box` скачивается системным `curl` с `--proto =https`,
  `--proto-redir =https` и `--max-redirs 3`.
- Ограничение: guard проверяет DNS-ответ в момент запроса, а соединение идёт
  по имени, поэтому между проверкой и подключением остаётся окно для
  DNS-rebinding. Модель угроз — доверенная LAN и уже рутованная колонка: это
  защита от подставных адресов в сценариях, подписке и обновлении, а не
  граница привилегий.

## Целостность обновлений и sing-box

- Обновление панели принимает только `https`-ассеты с хостов GitHub
  (`github.com`, `objects.githubusercontent.com`,
  `release-assets.githubusercontent.com`, `codeload.github.com`) и проверяет
  SHA-256 из release-ассета; размер архива ограничен 50 МБ. Это защита от
  случайной подмены/обрыва, но не независимая подпись: SHA лежит в том же
  релизе. План без ломки текущей установки — подписывать `.sha256` отдельным
  ключом (minisign/GPG), хранить публичный ключ в прошивке/репозитории и
  проверять подпись до `install.sh`; либо использовать GitHub artifact
  attestations. Ключи в репозиторий не добавляем.
- `sing-box` скачивается только по HTTPS с GitHub (официальный релиз
  SagerNet, `sing-box-<версия>-linux-arm64.tar.gz`), с лимитом размера 30 МБ.
  Хэш обязателен: для версии `1.10.7` SHA-256 закреплён в коде
  (`PINNED_SHA256` в `cgi-bin/vpn.py`). Ожидаемое значение выбирается по
  порядку: `MYPULT_SINGBOX_SHA256` → `/data/mypult/sing-box.sha256` →
  закреплённый хэш. Значение из переменной или файла принимается, только если
  это ровно 64 hex-символа (регистр не важен; из файла берётся первое слово,
  поэтому подходит вывод `sha256sum`); иначе молча используется пин. Если пина
  для версии нет и валидного хэша тоже, установка отказывается:
  «sing-box: нет SHA-256 для версии …». Несовпадение — «sing-box: SHA-256 не
  совпал»; проверка идёт до распаковки.
- Архив `sing-box` распаковывается самим `vpn.py` через `tarfile`
  (`filter="data"`), без `sh -c "gzip -dc | tar -xf"` — shell в этом шаге не
  участвует. Перед распаковкой проверяется каждый элемент: запрещены
  абсолютные пути и `..` в компонентах («небезопасный путь»), symlink и
  hardlink («ссылки в архиве запрещены»), а также всё, кроме обычных файлов и
  каталогов («неподдерживаемый элемент»). Ошибка архива — «не распаковался
  sing-box», установка прерывается.
- PIN сейчас 4–8 цифр для совместимости; существующие 4-значные PIN не
  ломаются. Рекомендуется 6–8; смена минимальной длины потребует отдельного
  UX-решения и миграции.

## Процессы и запись файлов

- Остановка процессов по pid-файлу не доверяет одному числу:
  `init.d/S99mypult` сначала проверяет `kill -0`, затем сверяет
  `/proc/<pid>/cmdline` с ожидаемым именем (`voice_daemon.py`,
  `state_daemon.py`, `lighttpd`, `luna`, `socat`). Если имя не совпало,
  процесс не трогается, в лог пишется «pid N не совпал — не трогаю», а
  pid-файл удаляется. Это защита от «осиротевших» pid-файлов после
  перезагрузки, когда тот же pid занял уже чужой процесс.
- `cgi-bin/voicectl.py` (`alive()`) и `cgi-bin/vpn.py` (`pid_alive()`)
  проверяют так же: `kill -0` плюс `/proc/<pid>/cmdline`
  (`voice_daemon.py` и `sing-box`). Если `/proc` недоступен, сохраняется
  прежнее поведение — достаточно `kill -0`.
- Сверка по cmdline защищает от случайного попадания в чужой pid, но не от
  процесса, который сам назвался ожидаемым именем. CGI и init-скрипт и так
  работают от root, поэтому это не граница привилегий.
- `common.write_json()` пишет JSON через уникальный временный файл
  `tempfile.mkstemp` в той же папке (`<файл>.XXXX.tmp`), затем `flush` +
  `fsync`, `chmod 600` и `os.replace`. При ошибке временный файл удаляется.
  Предсказуемого `<файл>.tmp` больше нет: посторонняя ссылка с таким именем
  не перехватывает запись, а параллельные записи не перемешиваются.
- Атомарна только замена файла: каталог не fsync-ается, поэтому при жёстком
  сбое питания возможна потеря последней записи, но не частичный JSON.

## В области действия

- обход PIN-гейта;
- выполнение команд/чтение файлов через CGI;
- утечка секретов из `/data/mypult`;
- CSRF/SSRF в CGI и прокси `/luna/`;
- ошибки авторизации в `/state` и `index.py`;
- повышение привилегий внутри уже запущенного пульта.

## Вне области действия

- получение root на колонке, прошивка, загрузчик;
- облачные сервисы Яндекса, Glagol, Luna, YAM и Entware;
- физический доступ к устройству;
- DoS в пределах собственной локальной сети;
- последствия включения VPN или установки сторонних пакетов.

## Safe harbor

Исследование безопасности на **своём** устройстве приветствуется.
Не атакуйте чужие колонки и не публикуйте данные других пользователей.
Автор не несёт ответственности за последствия экспериментов на устройстве.
