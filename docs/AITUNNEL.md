# AITUNNEL: провайдер, ошибки и модели (форк)

Этот репозиторий — форк [RoBiN19666/midipult](https://github.com/RoBiN19666/midipult).
В нём добавлен провайдер [AITUNNEL](https://aitunnel.ru), веб-поиск и понятные
сообщения об ошибках для работы нейросети на Станции Миди.

## Что изменено относительно upstream

Изменения затронули не только `cgi-bin/llm.py`, но и `service/voice_daemon.py`,
`deploy/aitunnel-profile.sh`, `index.html` и тесты.

### Провайдер AITUNNEL

В `PROVIDERS` (`cgi-bin/llm.py`) появилась запись с `id: aitunnel`:

- название — `AITUNNEL`;
- base URL — `https://api.aitunnel.ru/v1`;
- встроенный список моделей — `deepseek-v4.1-flash-1017`,
  `deepseek-v4.1-flash`, `sonar`;
- своя карта ошибок (`errors.types`, `errors.codes`, `errors.default`).

Профиль создаётся с `provider=aitunnel`; `deploy/aitunnel-profile.sh` больше
не использует `custom`. Пустой провайдер нормализуется в `openai`
(`normalize_provider`), поэтому старые конфиги без поля `provider` работают
как раньше.

### Веб-поиск AITUNNEL

Для профилей, у которых `base_url` содержит `aitunnel.ru`, в запрос
добавляется серверный инструмент:

```json
"tools": [{
  "type": "aitunnel:web_search",
  "parameters": {
    "engine": "parallel",
    "mode": "basic",
    "max_results": 3,
    "max_uses": 1
  }
}]
```

Модель сама решает, нужен ли поиск: на «какая погода» сходит в сеть,
на «17 × 23» — нет. Движок `parallel/basic` выбран потому, что корректно
работает с русским языком.

### Общие и провайдерские карты ошибок

В `llm.py` есть общий `BASE_ERRORS` по HTTP-кодам:

| Код | Текст |
|---|---|
| 400 | Нейросеть отклонила запрос |
| 401 | Ключ API не принят |
| 402 | Закончились средства на балансе нейросети |
| 403 | Доступ к нейросети запрещён |
| 404 | Модель не найдена |
| 408 | Сервис не ответил вовремя |
| 413 | Слишком большой запрос |
| 429 | Слишком много запросов подряд |
| 500 | Ошибка на стороне сервиса |
| 502 | Сервис нейросети недоступен |
| 503 | Сервис нейросети перегружен |
| 504 | Сервис не ответил вовремя |

Если кода нет в таблице, используется `default` — «Сервис нейросети не
отвечает».

У каждого провайдера может быть своя карта `errors`:

- `types` — по `error.type` из ответа API (например, `insufficient_balance`);
- `codes` — по HTTP-коду (например, `402`);
- `default` — общий текст провайдера.

Карта провайдера накладывается на общую: её `types` и `codes` дополняют
`BASE_ERRORS`, а `default` заменяет общий. Порядок выбора текста:

1. свои сообщения из панели (см. ниже);
2. карта провайдера по `error.type`, затем по `error.code`;
3. общие HTTP-коды (с учётом переопределений провайдера);
4. `default` провайдера.

Для AITUNNEL по документации сервиса заведены типы:

- `insufficient_balance` — «Закончились деньги на балансе AITUNNEL»;
- `budget_exceeded` — «Исчерпан бюджет ключа AITUNNEL»;
- `authentication_failed` — «Ключ AITUNNEL не принят»;
- `permission_denied` — «Ключу AITUNNEL запрещён этот запрос»;
- `model_not_found` — «Модель не найдена в AITUNNEL»;
- `not_found` — «AITUNNEL не нашёл запрошенный ресурс»;
- `invalid_request` — «AITUNNEL отклонил запрос»;
- `sensitive_data_blocked` — «Запрос заблокирован из-за чувствительных данных»;
- `rate_limited` — «Слишком много запросов к AITUNNEL»;
- `provider_error` — «Провайдер модели вернул ошибку»;
- `provider_unavailable` — «Модель сейчас недоступна»;
- `upstream_invalid_response` — «Провайдер вернул негодный ответ»;
- `service_unavailable` — «Сервис AITUNNEL временно недоступен»;
- `internal` — «Внутренняя ошибка AITUNNEL».

Переопределения по HTTP-кодам: `402` — «Закончились деньги на балансе
AITUNNEL», `403` — «AITUNNEL запретил запрос», `429` — «Слишком много запросов
к AITUNNEL», `503` — «AITUNNEL временно недоступен». Остальные коды берутся
из `BASE_ERRORS`. `default` провайдера — «AITUNNEL не отвечает».

### Свои сообщения об ошибках

В панели «Нейросеть» есть поле **«Свои сообщения об ошибках (активный
провайдер)»**. Формат — по строке `ключ=текст`:

```text
# комментарий
402=Кончились деньги, пополни AITUNNEL
insufficient_balance=Баланс AITUNNEL пуст
default=Нейросеть недоступна
```

- `#` в начале строки — комментарий, пустые строки игнорируются;
- ключом может быть `error.type`, `error.code` или HTTP-код;
- если подходят несколько ключей, порядок такой: тип ошибки, затем её код,
  затем HTTP-код, затем `default`;
- `default` — запасной текст;
- лимит — 4000 символов (иначе `413`).

Тексты хранятся в `llm.json` в `error_messages` отдельно для каждого
провайдера. Поле предзаполняется сообщениями текущего провайдера (с
комментариями «Типы ошибок провайдера» и «HTTP-коды»); статус рядом
показывает «Свои сообщения» или «Сообщения провайдера».

Если сохранить пустое значение, свои сообщения для активного провайдера
удаляются, и снова используются сообщения провайдера. Старое общее поле
`error_messages_text` поддерживается как fallback: оно читается, пока для
провайдера нет своих сообщений, а при сохранении из панели переносится в
`error_messages` (или просто удаляется, если поле пустое).

### Ошибки провайдера отдаются как HTTP 502

Любая ошибка API провайдера (включая его собственные `401` и `402`)
возвращается панели и демону как **`502`**, чтобы их нельзя было спутать с
PIN-блокировкой пульта или ошибкой биллинга. В теле ответа:

- `error` — короткий текст по карте ошибок или своим сообщениям;
- `hint` — сообщение провайдера, если оно было в ответе;
- `error_type` — `error.type` провайдера;
- `provider_status` — исходный HTTP-код провайдера;
- `detail` — сырой фрагмент ответа (до 400 символов).

Если связи нет совсем, также возвращается `502` с текстом «Нет связи с
сервисом нейросети» и подсказкой проверить интернет; для AITUNNEL в подсказке
предлагается `https://ru-api.aitunnel.ru/v1`. Пустой ответ модели — `502`
«Модель вернула пустой ответ».

### Список моделей

Список запрашивается **POST**-ом:

```text
POST /cgi-bin/llm.py
{"models": 1, "provider": "aitunnel", "base_url": "https://api.aitunnel.ru/v1"}
```

Ответ: `{"ok": true, "models": [...], "source": "key|public|builtin",
"provider": "aitunnel"}`.

Источники по порядку:

1. `GET <base_url>/models` с ключом — только если провайдер совпадает с
   активным профилем и `base_url` совпадает с его `base_url` (или не передан).
   Ключ чужого профиля не используется, иначе каталог был бы от другого
   сервиса;
2. публичный каталог AITUNNEL
   `https://api.aitunnel.ru/public/aitunnel/models`, группа `chat` — если
   провайдер `aitunnel` или в `base_url` есть `aitunnel`;
3. встроенный список моделей провайдера из `PROVIDERS`.

`GET` с полями `provider` или `base_url` запрещён (`405`): это mutating-ключи
из `WRITE_KEYS` в `common.py`. Рабочий вариант — `models=1` через POST.

В панели список загружается в селект **«Модель»**, кешируется по
`provider|base_url` и фильтруется от не-чат моделей (эмбеддинги, TTS/STT,
картинки, видео, модерация, реранкеры). Если после фильтра список не пуст,
показываются только чат-модели; если каталог недоступен, остаётся встроенный
список. Пункт «Другая модель…» позволяет ввести имя вручную.

### Озвучка ошибок

`service/voice_daemon.py` озвучивает не только ответ, но и сбой:

- ошибка LLM — «Нейросеть прилегла: <текст>. Спроси Алису.»;
- пустой ответ — «Нейросеть промолчала. Спроси Алису.»;
- таймаут (ответа нет через 30 секунд) — «Нейросеть не ответила вовремя.
  Спроси Алису.».

Текст ошибки берётся из поля `error` ответа `llm.py`, поэтому свои сообщения
из панели и карты провайдера слышны и в голосе.

## Установка

1. На колонке должен быть root, Entware и Luna на `127.0.0.1:8099`
   (см. основной README).
2. Создайте каталог веб-рута (установщик его не создаёт):

   ```sh
   mkdir -p /data/myweb
   ```

3. Скачайте форк и запустите установщик:

   ```sh
   cd /tmp && rm -rf mp && mkdir mp && cd mp
   wget -O f.zip https://github.com/MansurovAlexander/midipult/archive/refs/heads/main.zip
   unzip -q f.zip && cd midipult-main
   sh deploy/install.sh
   ```

   С Windows удобнее `deploy/push-to-station.ps1 -Station <IP>`.

## Настройка профиля AITUNNEL

Через панель: `http://<IP>:8055` → «Нейросеть» → в поле «Провайдер» выберите
**AITUNNEL** (это не «свой сервер»):

- Base URL: `https://api.aitunnel.ru/v1`;
- Модель: выберите из списка (по умолчанию `deepseek-v4.1-flash-1017`) или
  укажите вручную через «Другая модель…»;
- Ключ: `sk-aitunnel-...`.

Или на колонке одной командой:

```sh
sh deploy/aitunnel-profile.sh sk-aitunnel-...
```

Скрипт создаёт профиль с `provider=aitunnel`, делает его активным и включает
голосовой тумблер. Второй и третий аргументы необязательны:

```sh
sh deploy/aitunnel-profile.sh sk-aitunnel-... https://api.aitunnel.ru/v1 deepseek-v4.1-flash-1017
```

## Откат

- Вернуться на прежний профиль: «Нейросеть» → выбрать профиль чипом или
  голосом; скрипт не меняет другие профили и их ключи.
- Убрать AITUNNEL: удалите профиль в панели; голосом можно выключить
  нейросеть, но не удалить профиль. Ключ хранится в `/data/mypult/llm.json`
  с правами `600`.
- Полностью удалить пульт: `sh /data/mypult/uninstall.sh` (с `--purge` —
  вместе с ключами и настройками). Перезагрузка не требуется.

## Стоимость

- обычная реплика без поиска — около 0.01 ₽;
- реплика с веб-поиском — около 1 ₽ (движок Parallel, режим `basic`,
  один поиск на запрос, до 3 результатов).

Чтобы поиск был дешевле, можно поменять `engine`/`mode` на
`parallel/fast` (около 0.20 ₽), но он рассчитан на английский и японский;
для русского лучше оставить `basic`. Другой вариант — `exa` (около 1.40 ₽)
или `perplexity` (около 1 ₽).

## Синхронизация с upstream

```sh
git remote add upstream https://github.com/RoBiN19666/midipult.git
git fetch upstream
git merge upstream/main
```

Если upstream изменит затронутые файлы, при конфликте нужно сохранить правки
из раздела «Что изменено»: провайдер AITUNNEL, веб-поиск, карты ошибок,
свои сообщения, список моделей, `502` с `provider_status` и озвучку ошибок.

## Ограничения

- Веб-поиск включается только для профилей AITUNNEL (по `base_url`).
  Для других провайдеров поведение не меняется.
- Карта ошибок AITUNNEL — снимок документации сервиса. Если AITUNNEL добавит
  новые типы, их можно описать своими сообщениями в панели без правки кода.
- Правки не попадают в релизы upstream и не публикуются как пакет:
  установка идёт из исходников этого форка.
