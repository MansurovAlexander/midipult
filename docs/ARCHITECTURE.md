# Архитектура MidiPult

Документ описывает, из чего состоит пульт, как компоненты взаимодействуют,
где хранятся данные и что происходит при загрузке колонки.

---

## 1. Общая схема

```
Браузер (LAN)
   │  HTTP :8055
   ▼
lighttpd ── static /data/myweb/index.html
   │
   ├── CGI /cgi-bin/*.py  (Python 3, root)
   │      ├── Luna  http://127.0.0.1:8099
   │      ├── Glagol ws://127.0.0.1:1961
   │      ├── IPC TTS tcp://127.0.0.1:9875  (maind --platformd)
   │      ├── sysfs  (/sys/class/leds, /sys/class/backlight, i2c)
   │      └── /data/mypult/*.json
   │
   └── голосовой демон (отдельный процесс)
          ├── Luna recognize (микрофон)
          ├── сценарии / LLM / VPN / радио
          ├── планировщик расписания
          ├── автояркость
          └── отложенное восстановление громкости
```

Ключевая идея: панель не дублирует демонов Яндекса, а управляет ими через
локальные API и sysfs. Там, где API нет (Zigbee, прямой URL потока), пульт
честно показывает ограничение.

## 2. Компоненты

| Компонент | Роль |
|---|---|
| `lighttpd` | отдаёт статику и запускает CGI на `8055` |
| `index.py` | серверный вход: без PIN-куки отдаёт только страницу входа |
| `index.html` | SPA: вкладки, карточки, опрос состояния, drag-and-drop |
| CGI `cgi-bin/*.py` | вся логика: JSON-ответы, вызовы Luna/Glagol/sysfs |
| `voice_daemon.py` | распознавание, интенты, LLM, сценарии, планировщик |
| `state_daemon.py` | постоянный кэш статуса/плеера, системы и звуков на `127.0.0.1:8057`; статус — 2 с, плеер и система — 10 с, звуки — 30 с |
| `maind --platformd` | владелец IPC `9875`, TTS и части системных API |
| Luna | LED, дисплей, сенсоры, распознавание, медиа-состояние |
| Glagol | диалог, музыка, радио, громкость, `sendText` |
| `sing-box` | VPN, интерфейс `tun0` |
| `unbound` | DNS, конфиг `/etc/unbound/unbound.conf` |
| `bluealsad` | A2DP-приёмник Bluetooth |

Плюс два серверных маршрута вне `cgi-bin`:

- `index.py` (`/`) — проверяет PIN-куку и отдаёт либо страницу входа, либо
  `index.html`; прямой `/index.html` запрещён (403);
- `/state` — проксируется на `state_daemon.py` (`127.0.0.1:8057`), отдаёт
  лёгкий кэш статуса и плеера (~0,5 КБ); `?full=1` добавляет систему, диски,
  железо и звуки (~21 КБ). При сбое панель использует CGI-резерв;
- данные разделов загружаются лениво при открытии вкладки; `/state`
  опрашивается раз в 15 секунд, на «Звуке» — раз в 6 секунд.

CGI запускаются от root: иначе недоступны sysfs, `amixer`, `wpa_cli`.

## 5. Потоки данных

### Дисплей и часы

1. Время на дисплее ставит стандартная Алиса/Luna; панель его не переставляет.
2. `display.py` управляет яркостью, рисунком, бегущей строкой и гашением.
3. «Погасить экран» сохраняет рисунок и пишет нули во все LED.
4. Сброс дисплея возвращает яркость/автояркость/режим и очищает рисунок;
   сброс кольца отдельно возвращает цвет/яркость/эффект.

### Кольцо и яркость

1. Цвета уходят в Luna `/api/led/ring` (24 диода).
2. Яркость — это ток LED-контроллеров `1-0034/1-0035` (`current`), а не
   `fb0`: запись в `fb0` даёт краткую вспышку.
3. Значение сохраняется в `ring.json`; boot-скрипт и `display.py restore`
   возвращают его после загрузки.
4. Автояркость кольца читает `lux` из `/api/sensors` и пересчитывает ток;
   автояркость дисплея тем же `lux` пересчитывает яркость и отправляет её в
   Luna. Конфиг — `auto_brightness.json` (ключи `enabled/min/max` для кольца,
   `display_enabled/display_min/display_max` для дисплея).

### LLM и чаты

1. Панель или демон вызывает `llm.py {prompt, system}`.
2. `llm.py` берёт активный профиль и активный чат, добавляет последние
   10 сообщений, отправляет в OpenAI-совместимый API. Пустой провайдер
   считается `openai` (`normalize_provider` применяется в `info()`,
   `public_profile()` и `ask()`); если у провайдера нет встроенного `base_url`
   (например, `custom`), берётся `base_url` профиля.
3. Модель обязательна: если в профиле пусто, запрос не уходит, а возвращается
   `400` «Не выбрана модель» с подсказкой выбрать модель в панели.
4. `max_tokens` берётся из настроек панели (260/700/1400/2000, потолок 2000);
   для DeepSeek дополнительно `thinking: disabled`. Для профилей AITUNNEL
   в запрос добавляется серверный веб-поиск.
5. Ответ читается через `read_json_response` с лимитом **2 МБ**
   (`MAX_RESPONSE`). Обрезанный JSON, не-JSON или тело больше лимита — `502`
   «Неожиданный ответ API» с коротким `detail`, а не `500`. Текст достаёт
   `chat_answer()`: `choices[0].message.content`, если `content` равно `null` —
   `message.reasoning`, массив частей склеивается через пробел. Если текста
   нет, — `502` «Модель вернула пустой ответ».
6. Ошибки провайдера переводятся по цепочке «свои сообщения → карта
   провайдера (тип/код) → общие HTTP-коды → default» и всегда отдаются как
   `502` с полем `provider_status`, чтобы не путать их с PIN или биллингом.
7. Список моделей — POST `models=1`. Ключ активного профиля используется,
   если провайдер совпадает, а `base_url` либо не передан (тогда берётся
   дефолтный base провайдера), либо совпадает с base активного профиля.
   Иначе — публичный каталог AITUNNEL (при `provider=aitunnel` или если в
   `base_url` есть `aitunnel`) или встроенный список провайдера.
8. В панели `base_url` профиля выставляется в форму **до** загрузки моделей:
   `applyProfile()` подставляет base, затем `fillModels()` строит список.
   `fillModels()` не затирает непустой base дефолтом провайдера,
   `selectProvider()` ставит base нового провайдера (для `custom` — пусто),
   ручная смена base перезагружает модели. Кеш моделей ключуется
   `provider|base_url|key/no-key`; `key` ставится только если провайдер
   совпадает с активным на сервере профилем с ключом, а base пуст или совпадает
   с его base — как в `fetch_models`.
   Кеш сбрасывается при сохранении профиля и смене активного профиля, ключа
   или base активного серверного профиля; смена base в форме даёт другой ключ
   кеша. Ответ устаревшего запроса игнорируется. Не-чат модели отсекает
   `MODEL_BLOCK`: эмбеддинги, TTS/STT (включая `openai/tts-1`),
   `audio`/`realtime`, картинки, видео, модерация, реранкеры.
9. Id профиля стабилен: `profile_id` и id профилей сравниваются через
   `slug()` (нижний регистр, до 40 символов) без учёта регистра; повторный
   запуск скрипта обновляет существующий профиль. Суффиксы новых профилей
   считаются от корня имени: `chatgpt`, `chatgpt-2`, `chatgpt-3`.
10. Ответ и вопрос дописываются в чат (до 20 сообщений), сохраняются в
    `chats.json`.
11. В ответе возвращаются `usage` (токены), имя чата и профиля.

### Голос

1. Демон вызывает Luna recognize и получает текст.
2. Одинаковые фразы в течение 30 секунд игнорируются.
3. Перед разбором `should_silence()` решает, глушить ли штатную Алису. Она
   вызывает `llm_switch(..., dry_run=True)` — это только проверка сценария без
   POST и озвучки, профиль/чат не переключаются. Реальное переключение одно, в
   `handle()`, поэтому нет двойного «Включаю…» и двойной паузы музыки.
4. Сначала отбрасывается «список радио» («какие радио…»), чтобы Алиса не
   успела ответить, пока ждём `scenarios.py`. Дальше порядок разбора:
   сценарий → переключение LLM/чата → встроенные интенты → LLM.
5. Сценарий вызывается только если `scenario_may_match()` нашёл фразу в
   `/data/mypult/scenarios.json`. Нет файла или он не читается — функция
   возвращает `False`, CGI не дёргается, Алиса не глушится на каждую фразу.
   Список фраз кешируется по mtime; после правки файла читается заново.
6. `match()` и `llm_switch()` отличают вопрос от императива: фразы с «?»,
   «ли», «как», «можно», «что такое» и подобные не выполняются, а «какой чат?»
   и «какая нейросеть?» остаются информационными. Императив в начале фразы
   («включи впн», «пожалуйста, включи впн») работает.
7. Перед отправкой в LLM проверяются исключения: «свет» — зона реле, а
   `alice_owns()` срезает вводные слова и распознаёт команды плеера по началу
   фразы. Поэтому «пожалуйста, следующий» и «сделай погромче» остаются Алисе,
   а вопросы вроде «почему не работает звук?» доходят до LLM.
8. Перед собственным ответом демон отправляет Glagol `sendText «стоп»` —
   это отменяет TTS Алисы (`cancelDirective`), а не глушит звук.
9. Своё подтверждение читается через `speak.py`; для профилей дополнительно
   ставится пауза музыки.

### Сценарии и расписание

1. Сценарий — JSON: имя, фразы, действия, `schedule`, `conditions`.
2. Планировщик в демоне каждые 30 секунд вызывает `scenarios.py {tick:1}`.
3. `tick` сравнивает локальное время станции, дни и условия; один сценарий
   выполняется не чаще раза в минуту.
4. Действия выполняются по порядку; HTTP-действие — GET с таймаутом 10 с.

### Громкость

1. `volume.py` управляет `Master` через amixer; при mute запоминает уровень.
2. Уровень сохраняется в `volume.json`.
3. После загрузки maind выставляет свои ~40%; демон через 20 секунд
   возвращает сохранённое значение.

### VPN и бинарник sing-box

1. `vpn.py` проверяет, что `/data/mypult/bin/sing-box` существует и исполняемый.
   Если нет, скачивается официальный архив
   `sing-box-1.10.7-linux-arm64.tar.gz` с GitHub (`curl` с `--proto =https`,
   `--proto-redir =https`, `--max-redirs 3`) в `/tmp`; размер архива должен
   быть больше нуля и не больше 30 МБ.
2. Ожидаемый SHA-256 выбирается по порядку: `MYPULT_SINGBOX_SHA256` →
   `/data/mypult/sing-box.sha256` → закреплённый в коде `PINNED_SHA256`
   (для `1.10.7` — `15b43a0a50b4e6962aca819d4f3055aaac75ca7481350d4aaebe93ed06b7af49`).
   Значение из переменной или файла принимается, только если это ровно
   64 hex-символа (регистр не важен, из файла берётся первое слово — подходит
   вывод `sha256sum`); иначе молча используется пин. Переменную нужно задавать
   в окружении запуска CGI: lighttpd не пробрасывает окружение сессии.
3. Если ни env/файл, ни пин не дали корректного хэша, установка прерывается:
   «sing-box: нет SHA-256 для версии 1.10.7». Несовпадение хэша —
   «sing-box: SHA-256 не совпал»; распаковка в этом случае не начинается.
4. Архив распаковывается `tarfile` (`filter="data"`), без `sh -c`, после
   проверки каждого элемента: запрещены абсолютные пути и `..` в компонентах,
   symlink и hardlink, а также всё, кроме обычных файлов и каталогов. Ошибка
   даёт «не распаковался sing-box».
5. Найденный в распакованном дереве файл `sing-box` переносится в
   `/data/mypult/bin/sing-box` и получает права `755`.

## 7. Загрузка колонки

Голосовой тракт: демон получает текст через Luna `recognize` только после
финального распознавания, а штатный диалог Алисы стартует раньше. Поэтому
отмена TTS всегда с гонкой; ограничения и обходы —
[VOICE-LIMITS.md](VOICE-LIMITS.md).

```
/etc/init.d/rcS
  └── /etc/init.d/S99mypult        (шим на ro-rootfs)
        └── /opt/etc/init.d/S99mypult start
              ├── start_ipc         (socat/порт 9875 при необходимости)
              ├── start_luna        (8099)
              ├── start_web         (lighttpd 8055)
              ├── restore_volume    (volume.json)
              ├── start_voice       (voice_daemon.py + voice.pid)
              ├── start_state       (state_daemon.py на 8057)
              ├── start_ring_backlight (ring.json → ток)
              ├── start_dns_auto
              └── start_vpn_auto    (если autostart)
```

`start_voice` вызывает `voicectl.py {start:1}` и проверяет `voice.pid`.
Голосовой демон поднимает потоки: расписание, автояркость, отложенную
громкость и автоочистку диска. `start_state` запускает постоянный кэш
`/state`; если он не поднялся, панель использует CGI-резерв.

Остановка и повторный запуск не доверяют одному числу из pid-файла:
`pid_matches(pid, имя)` проверяет `kill -0`, затем наличие ожидаемого имени в
`/proc/<pid>/cmdline` (`voice_daemon.py`, `state_daemon.py`, `lighttpd`,
`luna`, `socat`). Имя ищется как подстрока в строке cmdline, поэтому для
демонов достаточно имени скрипта или бинарника. Если cmdline не совпал,
процесс не трогается, в лог идёт «pid N не совпал — не трогаю», а pid-файл
удаляется. Так после перезагрузки не убивается чужой процесс, получивший тот
же pid. Если `/proc/<pid>/cmdline` прочитать нельзя, `pid_matches` считает
совпадение доказанным (совместимость со старыми сборками). `stop_pidfile`,
`stop_voice`, `stop_state`, `reload_web` и проверки в `start_voice` /
`start_state` используют одну и ту же функцию.

Свой `stop_pidfile(file, needle)` есть и в `deploy/uninstall.sh`: он следует
той же схеме для voice/state/lighttpd, но с двумя отличиями — pid читается
только из цифр и отбрасываются пустой pid и pid с ведущим нулём (`kill 0`
убил бы группу процессов), а сообщение при несовпадении — «pid N не похож на
… — не трогаю». Подробности — в §8.

`reload` **полностью** перезапускает web, голос и state: SIGHUP в этой сборке
не перечитывает конфиг lighttpd. `restart` перезапускает весь стек, `stop`
останавливает только то, что запустил сам. Помощник `reload_web` (SIGHUP при
совпадении cmdline, иначе перезапуск) в текущем `case` не вызывается:
ветка `reload` идёт через `stop_web` и `start_web`.

## 8. Деплой

`deploy/install.sh`:
1. создаёт каталог веб-рута `/data/myweb` (`mkdir -p`) и запускает
   `deploy/preflight.sh`: модель `/proc/device-tree/model` (Cucumber/Midi),
   root, Entware, `opkg`, пакеты (`python3`, `lighttpd`, `mod_cgi`,
   `mod_proxy`, `curl`), Luna, IPC, свободное место на `/` и `/data`;
   недостающие пакеты ставит через `opkg`, а `websocket-client` — сразу через
   `python3 -m pip install`: opkg-пакета `python3-websocket-client` в Entware
   нет, поэтому `opkg` для него не вызывается; при `MYPULT_NO_PACKAGES=1`
   preflight ничего не устанавливает, отсутствие модуля — только
   предупреждение;
2. копирует `index.html`, `index.py`, `manifest.json`, `favicon.ico`,
   `icon-192.png`, `icon-512.png`, `icon.png`, CGI, конфиг, init и демоны;
3. проверяет `lighttpd -t`;
4. делает бэкап старых конфигов и файлов в `/tmp/mypult-backup-<дата>`;
5. вызывает `reload`: web + voice + state (панель пропадает на 2–3 секунды,
   зато конфиг применяется);
6. проверяет, что панель и CGI отвечают.

`deploy/push-to-station.ps1` задуман так: находит колонку, считает хэш,
поднимает патч-версию, шлёт tar по SSH и запускает install; флаги `-Station`,
`-NoBump`, `-NoInstall`, `-NoScan`, `-Message`. В текущем состоянии файл
повреждён (смешанная кодировка UTF-16LE/UTF-8) и PowerShell его не
выполняет; `push.cmd` вызывает тот же скрипт. Это pre-existing дефект,
исправление — отдельной задачей; до неё установка идёт через
`deploy/install.sh` на колонке.

`deploy/uninstall.sh` останавливает только процессы пульта, делает бэкап в
`/data/mypult-uninstall-<дата>`, удаляет `/data/myweb`, init-скрипты и
`myweb.conf`. Luna/YAM/Entware не затрагиваются; `--purge` дополнительно
удаляет `/data/mypult`, `--dry-run` только показывает план.

Остановка не доверяет одному числу из pid-файла. `stop_pidfile(file, needle)`
читает из файла только цифры (`tr -dc '0-9'`); пустой pid и pid, начинающийся
с нуля (`0*`), считаются негодными — `kill 0` убил бы всю группу процессов, —
и pid-файл просто удаляется. Для `/data/mypult/voice.pid`,
`/tmp/mypult-state.pid` и `/tmp/mypult-lighttpd.pid` передаются ожидаемые
имена `voice_daemon.py`, `state_daemon.py` и `myweb.conf`; если в
`/proc/<pid>/cmdline` этого имени нет, печатается «pid N не похож на … — не
трогаю», процесс остаётся жив, а pid-файл удаляется. Если `/proc/<pid>/cmdline`
прочитать нельзя, остаётся проверка `kill -0` — как в init-скрипте. В
`--dry-run` сигналы не посылаются и файлы не удаляются: kill и `rm` только
печатаются.

## 10. Безопасность

- PIN опционален (по умолчанию выключен) и проверяется **на сервере**:
  - `/` обслуживает `index.py`: без куки — страница входа, с кукой — SPA;
  - `/index.html` запрещён в lighttpd (403);
  - `common.require_auth()` вызывается из `params()` и `respond()`, поэтому
    любой CGI без куки с LAN получает 401;
  - `/state` проверяет куку в state-демоне.
- Localhost (сам пульт и демоны) проходит без PIN.
- Кука `mypult_token` — HttpOnly, SameSite=Lax, 30 дней; смена PIN
  инвалидирует старые сессии; «Заблокировать» сбрасывает текущую.
- HTTPS не используется: самоподписанный сертификат даёт предупреждение,
  Let's Encrypt требует публичный домен.
- Исходящие запросы: `common.url_guard()` проверяет схему, отсутствие
  `user:pass` в URL, резолвит хост и отклоняет link-local/метаданные,
  `0.0.0.0` и multicast (всегда), loopback и приватные сети (если они не
  разрешены флагом или allowlist `/data/mypult/url_allow.json`).
  `common.open_url()` — обёртка над `urlopen` с `GuardedRedirectHandler`:
  каждый redirect (301/302/303/307/308) проверяется тем же guard, а
  `same_host=True` дополнительно запрещает смену хоста и порта. Guard смотрит
  DNS-ответ в момент запроса; окно для DNS-rebinding между проверкой и
  соединением остаётся, модель угроз — доверенная LAN.
- Режимы проверки: HTTP-действия сценариев — `http(s)` и приватная LAN,
  loopback только через allowlist; VPN-подписка — публичный `https`; LLM
  `ask`/`fetch_models` — `same_host` (ключ не уходит на чужой хост, в `ask`
  это `502` «Неожиданный ответ API»); `update.py` — `api_guard`
  (`api.github.com` и хост `MYPULT_UPDATE_API` при условии публичного
  `https`) для списка релизов и `asset_guard` (`github.com`,
  `objects.githubusercontent.com`, `release-assets.githubusercontent.com`,
  `codeload.github.com`) для SHA и архива, на каждом хопе. `sing-box`
  качается `curl` с `--proto =https --proto-redir =https --max-redirs 3`.
- `sing-box` (`vpn.py`): хэш архива обязателен. Порядок — `MYPULT_SINGBOX_SHA256`
  → `/data/mypult/sing-box.sha256` → закреплённый `PINNED_SHA256`
  (для `1.10.7`). Некорректный формат переменной или файла не отключает
  проверку, а откатывается на пин; без пина и без валидного хэша установка
  отказывается. Распаковка — через `tarfile` с `filter="data"` и запретом
  `..`/абсолютных путей, symlink/hardlink и не-файлов (см. §5).
- Секреты — `600`, JSON пишется атомарно (уникальный tmp в той же папке,
  `fsync`, `os.replace`); бэкап содержит ключи, хранить отдельно.
- Остановка процессов по pid-файлу сверяет `/proc/<pid>/cmdline`; при
  несовпадении процесс не трогается. Это делают и init-скрипт (§7), и
  `deploy/uninstall.sh` (§8); uninstall дополнительно отсекает пустой pid и
  ведущие нули, потому что `kill 0` убил бы группу процессов.
- CGI от root — необходимо для sysfs/amixer/wpa_cli.
- Порт 8055 нельзя публиковать в интернет.

## 11. Ограничения

- **Zigbee**: локального API управления нет; только статус и список.
- **Spotify**: glibc 2.27 в Entware не совместим с готовыми клиентами.
- **Прямые URL потоков** и **лайки**: Glagol `UNSUPPORTED`.
- **ASR без wake-word** не реализован.
- **Остановка Алисы** — через `sendText «стоп»`; при позднем старте TTS
  возможны первые слоги.
- **Статический IP** и HTTPS не реализованы.
- **Самообновление из панели** смотрит в форк `MansurovAlexander/midipult`,
  но релизов панели там пока нет: панель отвечает «Релизы панели не найдены»
  и upstream-обновление не предлагает. Обновление заработает после релиза с
  `midipult-<версия>.tar.gz` и `.sha256`. `MYPULT_UPDATE_REPO` и
  `MYPULT_UPDATE_API` — dev-переопределения; с устройства окружение lighttpd
  не пробрасывается, их нужно задавать в init-скрипте/окружении запуска.
  Хост из `MYPULT_UPDATE_API` тоже обязан быть публичным `https`: loopback и
  приватные адреса отклоняются, redirect проверяется на каждом хопе.
- **FastCGI** в сборке отсутствует (`mod_fastcgi`/`flup`); горячий `/state`
  обслуживает отдельный локальный демон.

## 12. Оптимизации

- `/state` — один запрос вместо `status.py` + `player.py`; постоянный демон
  отдаёт кэш за ~5 мс, CGI-резерв остаётся.
- Атомарная запись JSON — уникальный `tempfile.mkstemp` в той же папке
  (`<файл>.XXXX.tmp`), `fsync`, `chmod 600`, `os.replace`; при ошибке
  временный файл удаляется. Предсказуемого `<файл>.tmp` нет, поэтому
  параллельные записи не перемешиваются, а посторонняя ссылка с таким именем
  не перехватывает запись. Каталог не fsync-ается: при жёстком сбое питания
  возможна потеря последней записи, но не частичный JSON. Так пишутся настройки
  LLM, чаты, сценарии, PIN и счётчик попыток, громкость, кольцо и автояркость,
  радио, VPN, DNS, IPv6, состояние обновления и бэкап. Временные файлы
  `/tmp/mypult-clock.json` и `/tmp/mypult-mute.json` пишутся обычным
  `open(..., "w")` — настройками они не являются.
- Кольцо: «дыхание» на 10 fps, кадры не отправляются при скрытой вкладке.
- Автоочистка логов и `__pycache__` при занятости диска >85%.
